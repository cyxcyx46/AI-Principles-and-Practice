### 任务描述
本关任务：在 `multiAgents.py` 中实现极小极大（`Minimax`）算法，为 `Pacman` 设计一个具备规划能力的对抗搜索智能体（`MinimaxAgent`）。

相较于仅着眼于当前局部状态的反射型智能体，本关卡的智能体将通过递归搜索技术遍历未来的游戏状态空间。在综合评估 `Pacman` 与多幽灵交替博弈的基础上，系统将寻求在有限深度内可实现绝对收益最大化的最优决策，从而在复杂动态环境中展现出更为卓越且深远的战略把控能力。

### 相关知识
为了完成本关任务，你需要掌握：1. 极小极大算法核心原理；2. 多重 `Min` 节点架构；3. 搜索树深度与终止条件；4. `Pacman` 多智能体状态交互`API`。

#### 极小极大算法核心原理

极小极大算法是经典的零和博弈（`Zero-Sum Game`）决策模型，广泛应用于“智能体收益完全对立”的对抗场景（如 `Pacman` 吞食得分与幽灵捕杀致损）。其核心假设建立在博弈双方的“绝对理性”之上：`Max` 智能体（即 `Pacman`）始终致力于选取能使自身状态评估函数收益最大化的策略；而 `Min` 智能体（即幽灵体系）则处于绝对对立面，始终试图将 `Pacman` 的收益最小化。在决策推演时，`Pacman` 需前瞻性地假设在自身采取任一行动后，幽灵必将做出最致命的反击。最终，系统将在所有可能的“最坏情况”中，挑选出一个能保障自身“保底收益”最大的动作。

在多智能体对抗场景下，极小极大算法的搜索过程可具象化为一棵严密的搜索树结构：根节点代表当前待决策的初始状态；`Max` 层对应 `Pacman` 所有合法动作的后继状态集合，其节点向上传递的值取其所有子节点的最大值；`Min` 层对应各幽灵合法动作的后继状态，其节点值取子节点的最小值。

#### 多重 `Min` 节点架构
传统的 `Minimax` 算法多用于描述严格的双人交替博弈（如国际象棋的黑白对弈）。然而，`Pacman` 游戏环境中存在多个独立幽灵，这构成了“单一 `Max` 节点对抗由多个 `Min` 节点组成的联盟”的非对称博弈结构。

根据游戏引擎的底层调度规则，智能体将按照固定索引依次行动：`Pacman` 率先行动（索引固定为 0），随后幽灵 1、幽灵 2 直至幽灵 N 依次响应。映射至代码的递归逻辑中，这意味着一个 `Max` 节点向下展开时，衔接的并非下一个 `Max` 节点，而是连续的多个 `Min` 节点序列。唯有当场上所有幽灵均完成一次推演后，一个完整的博弈回合才宣告结束，决策权方重新交还至下一深度的 `Pacman`。

####  搜索树深度与终止条件

本实验中的 `MinimaxAgent` 继承自基础类 `MultiAgentSearchAgent`，内置了搜索深度阈值参数 `self.depth` 与叶子节点评估函数 `self.evaluationFunction`。

在极小极大算法的实现中，深度的计量单位被严格定义为“包含 `Pacman` 与所有幽灵在内的一轮完整博弈回合”。例如，若设定 `self.depth = 2` 且环境中存在两只幽灵，系统将先推演 `Pacman`、幽灵 1 与幽灵 2 的相继行动以完成第 1 个深度层级；随后以此类推完成第 2 个深度层级。一旦递归推演达到预设的深度限制，或在推演中途提前触发了游戏的终局状态（胜利 `isWin()` 或失败 `isLose()`），递归流必须即刻终止，并调用评估函数返回该叶子节点的状态量化得分。

**关键逻辑伪代码**

```
函数 maxVal(gameState, depth):
    深度 depth = depth + 1   // 进入 Pacman 的回合代表开启新的深度层级
    若 达到目标深度 或 游戏胜利/失败:
        返回 evaluationFunction(gameState)
    初始化最大值为 -∞
    获取 Pacman 合法动作（移除 STOP 动作以防原地等死）
    对每个动作:
        生成后继状态
        // 下一步交给幽灵 1 (index=1)
        最大值 = max(最大值, minVal(后继状态, depth, 1))
    返回 最大值

函数 minVal(gameState, depth, index):
    若 游戏胜利/失败: // 幽灵行动前也可能游戏已结束
        返回 evaluationFunction(gameState)
    初始化最小值为 +∞
    获取 当前幽灵(index) 合法动作（移除 STOP）
    对每个动作:
        生成后继状态
        若 index == 最后一个幽灵:
            // 幽灵全走完了，下一轮交回给 Pacman (进入下一深度)
            最小值 = min(最小值, maxVal(后继状态, depth))
        否则:
            // 还没轮完，交给下一个幽灵 (同深度)
            最小值 = min(最小值, minVal(后继状态, depth, index + 1))
    返回 最小值

主函数 getAction(gameState):
    初始化 depth = 0, 最优值 = -∞, 最佳动作 = STOP
    获取 Pacman 初始合法动作（移除 STOP）
    对每个动作:
        // 在根节点，直接调用幽灵 1 评估其后继状态
        当前动作得分 = minVal(生成的后继状态, depth, 1)
        若 当前动作得分 > 最优值:
            更新 最优值 和 最佳动作
    返回 最佳动作
```

### 编程要求

根据提示，在 `multiAgents.py` 中 `MinimaxAgent` 的 `getAction` 方法内（`BEGIN-END` 之间）补充极小极大算法核心逻辑，步骤如下：

1. 定义 `Max` 层函数 `maxVal`(`gameState`, `depth`)：

- 初始化评估值为 `-9999`，深度自增 1；
- 检查终止条件：`depth == self.depth` 或 `gameState.isLose()` 或 `gameState.isWin()`，满足则直接返回 `self.evaluationFunction(gameState)`；
- 获取 `Pacman` 动作并移除 `STOP`。遍历所有合法动作，生成后继状态；
- 递归调用 `minVal(successState, depth, 1)`，用 `max()` 更新并返回最大值。



2. 定义 `Min` 层函数 `minVal`(`gameState`, `depth`, `index`)：

- 初始化评估值为 `9999`；
- 检查终止条件：游戏胜负已定，返回评估函数值；
- 获取当前幽灵动作并移除 `STOP`。遍历所有合法动作，生成后继状态；
- 判断流转：若当前是最后一个幽灵（`index == gameState.getNumAgents() - 1`），递归调用 `maxVal`；否则递归调用下一个幽灵的 `minVal (index + 1)`；
- 用 `min()` 更新并返回最小值。

3. 实现主函数逻辑 (`getAction`)：
- 移除 `Pacman` 初始动作中的 `STOP`；
- 遍历所有初始动作，调用 `minVal` 计算极小极大值；
- 选择极小极大值最大的动作作为最终结果返回。
