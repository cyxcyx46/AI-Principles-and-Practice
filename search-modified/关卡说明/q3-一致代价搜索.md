#### 一致代价搜索

一致代价搜索（`Uniform Cost Search`，`UCS`）是一种经典的无信息搜索算法，属于基于路径代价进行决策的搜索策略。与深度优先搜索和广度优先搜索仅依赖搜索深度或节点生成顺序不同，`UCS` 的核心思想是：始终优先扩展从初始状态到当前状态的累计路径代价最小的节点。因此，`UCS` 的搜索顺序完全由路径代价函数所决定，而不依赖于搜索树的深度或后继节点的生成顺序。

在实现层面，这一“按累计代价排序”的思想并不是通过普通队列或栈完成的，而是通过优先队列实现。优先队列会自动保证优先级，即路径代价，最小的节点最先被弹出，例如在初始化时，起始状态以代价 `0` 被压入优先队列：

```python
new.push(problem.getStartState(), 0)

```
这里的第二个参数即为节点的优先级，对应从起点到该状态的累计路径代价。

在一致代价搜索中，搜索问题被建模为一个带权状态空间，其中每一步动作都可能具有不同的代价 `step cost`。路径的总代价通常表示为:

```latex
g(n) = \sum_{i=1}^{k} cost(action_i)
```
其中 `g(n)` 表示从初始状态到节点 `n` 的累计路径代价。`UCS` 在搜索过程中始终选择当前 `g(n)` 值最小的节点进行扩展，从而逐步向代价更低的路径推进。

这一累计代价并不是抽象存在的，而是通过问题接口显式计算得到。例如，当从当前路径 `goalpath` 扩展一个新动作 `action` 时，其对应路径代价可以表示为：

```python
pathCost = problem.getCostOfActions(goalpath + [action])

```

该值随后被用作优先队列中节点的排序依据，从而直接体现了公式中 $$g(n)$$ 的计算过程。



一致代价搜索具有最优性保证。只要问题满足以下条件：

- 每一步的代价 非负（`step cost ≥ 0`）

- 搜索空间是有限的，或至少不存在负代价环

那么 `UCS` 第一次到达目标状态时，对应的路径一定是从初始状态到目标状态的最低总代价路径。这一性质使 `UCS` 成为求解带权最短路径问题的标准方法，其理论基础与 `Dijkstra` 算法高度一致。

在实现中，这一“第一次到达目标即最优”的性质依赖于如下事实：优先队列每次弹出的都是当前累计代价最小的节点。因此，一旦某个目标状态被从队列中弹出，其对应路径的代价已经不可能再被更小的路径所改进。

#### 代价函数的作用

在搜索问题中，**代价函数（Cost Function）** 用于刻画从一个状态执行某个动作所需付出的“消耗”，其定义直接决定了搜索算法对“最优路径”的理解方式。

形式化地，一个搜索问题可表示为五元组：
```latex
\langle S, A, T, c, G \rangle
```

其中：$$S$$ 为状态空间；$$A(s)$$是状态，$$s$$ 下可执行的动作集合；$$T(s, a)$$表示状态转移函数； **$$c(s, a, s')$$为代价函数**；$$G$$是目标状态集合。


在代码层面，`c(s, a, s')` 由搜索问题通过后继函数返回，例如：
```python
for next, action, cost in problem.getSuccessors(currstate):

```
其中的 `cost` 即为执行该动作所对应的单步代价。


对于一条路径 $$P = \langle s_0, s_1, \dots, s_n \rangle$$，其总代价定义为：

```latex
g(P) = \sum_{i=0}^{n-1} c(s_i, a_i, s_{i+1})
```

在 **一致代价搜索** 中，搜索的目标不是“步数最少”，而是寻找使累计代价 $$g(P)$$ 最小的路径。


例如，在扩展后继节点时，状态与其对应路径会被以相同的优先级压入各自的优先队列：
```python
new.push(next, pathCost)
path.push(goalpath + [action], pathCost)

```
这保证了状态与路径在逻辑上的一一对应关系，从而在到达目标状态时可以直接返回正确的最优动作序列。
