### 任务描述


本关任务：编写能够访问迷宫中的四个角落，并返回覆盖所有角落的完整动作路径的程序。


### 相关知识


为了完成本关任务，你需要掌握：

1. 状态表示与信息封装；

2. 后继函数设计与角落访问更新；
3. 目标状态判定；
4. 图搜索与重复状态避免；
5. 路径记录与最短路径搜索。

#### 状态表示与信息封装
在搜索问题建模中，状态的表示与信息封装是算法正确性和效率的基础。在某些环境中，单纯记录当前位置是不够的，因为问题的目标不仅仅是到达终点，还包含对路径中关键位置或条件的满足要求。例如，在四角访问类问题中，智能体需要访问多个指定目标点才能完成任务。为了使搜索算法能够正确判断目标是否达成，状态中必须包含足够的信息来表示任务进展情况。

具体来说，状态通常由一个位置表示和一个任务进展记录组合而成。
 
```python
state = (pacman_position, visited_corners)

```

其中， `pacman_position`是当前坐标 `(x, y)` ； `visited_corners`是长度为 `4` 的布尔列表 `[False, False, False, False]`，标记四个角落是否已访问；初始状态为未访问任何角落。

```python
start_state = (self.startingPosition, [False, False, False, False])

```

在初始化阶段，智能体所在的初始位置会被记录下来，同时任务进展列表被设置为未访问状态。随着搜索的进行，每当智能体到达某个关键目标点，相应的布尔标记会被更新为已访问。这种设计方式使得搜索算法能够在状态信息中直接获取目标完成情况，无需额外的全局变量或复杂的判断逻辑，从而简化了路径规划的实现。


#### 后继函数设计与角落访问更新

后继函数的设计是确保路径规划正确性和完整性的核心环节。对于包含多目标访问的搜索问题，仅仅更新智能体的位置是不够的，因为算法必须同时跟踪哪些关键目标已经被访问过。为此，后继函数在生成下一步状态时，需要同时更新当前位置和任务进展信息。

```python
if next_position in self.corners:
    idx = self.corners.index(next_position)
    next_corners[idx] = True

successors.append(((next_position, next_corners), action, 1))

```
代码中，`next_position`是下一步的坐标； `next_corners` 是根据下一步是否到达角落更新布尔列表； `action`是本步动作；`1` 为每步的代价。

当智能体向某个方向移动到下一步位置时，首先检查该位置是否为关键目标点之一。如果是，则在状态中的布尔列表中将对应标记更新为已访问状态 `True`；否则保持原有状态不变。随后，将更新后的状态、执行该动作的动作标记以及本步的代价信息一起加入到后继节点列表中。这样，每个后继节点就完整封装了智能体当前位置、任务进展以及从起点到该节点所采取的动作和成本信息，为搜索算法的后续扩展提供了完整依据。


#### 目标状态判定
在多目标搜索问题中，单纯依赖智能体的当前位置坐标无法判断任务是否完成，尤其是在要求访问多个关键位置的情况下。以四角访问类问题为例，任务完成的条件是智能体必须访问所有四个角落，而仅记录当前位置无法体现哪些角落已经被访问过，因此算法无法准确判断目标状态的达成。为此，状态设计中引入了角落访问布尔列表，用于记录每个角落是否已经被访问过，从而为目标判定提供可靠依据。

```python
def isGoalState(self, state):
    return all(state[1])

```
- `state[1]` 是角落访问布尔列表；

- `all(state[1])` 仅当四个角落都为 `True` 时返回 `True` 。

在实现中，目标判定函数通过检查状态中的角落访问布尔列表来确定任务是否完成。例如，可以使用内置的 `all()` 函数对布尔列表进行检查：仅当列表中所有元素均为 `True` 时，说明智能体已经访问了四个角落，任务完成。该方法简洁高效，避免了对每个角落逐一判断的繁琐操作，同时保证了判定过程的准确性。在搜索过程中，当算法取出一个状态并发现 `all(state[1])` 为真时，即可认定目标达成，并立即停止搜索，返回从起点到该状态的动作序列。


#### 图搜索与重复状态避免

在迷宫搜索中，智能体可能会多次经过同一位置，但在不同路径下，关键任务的完成情况可能不同。例如，在多目标访问问题中，同一个坐标点可能对应不同的角落访问组合。如果算法仅根据当前位置判断状态是否已访问，就会错误地认为这些状态相同，从而忽略尚未完成的任务。这不仅会导致搜索算法重复扩展相同状态，浪费计算资源，还可能在某些情况下陷入死循环，无法正确完成任务。

为了解决这一问题，项目中采用了**状态闭集（closed set）** 机制，在扩展节点前对当前状态进行检查。每个状态不仅包含智能体的当前位置，还封装了角落访问情况，形成一个完整的状态表示 `(position, visited_corners)`。

```python
if currstate not in closed:
    closed.append(currstate)

```

在扩展后继节点之前，算法先判断当前状态是否已存在于闭集中，只有未出现过的状态才会被加入搜索前沿并进一步展开。这保证了即使智能体回到同一坐标，只要角落访问情况不同，该状态仍会被单独扩展，从而完整覆盖所有可能的任务完成路径。


#### 路径记录与最短路径搜索

在多目标迷宫搜索中，任务不仅要求智能体访问所有关键位置，还要求返回从起点到目标状态的完整路径。每个搜索节点不仅需要记录当前位置和任务进展，还必须保存从起点到当前节点的动作序列，以便在搜索完成时直接生成完整的移动方案。为了实现这一要求，后继函数在生成每个新状态时，会将当前动作附加到父节点的动作序列中，形成新的路径信息。

```python
successors.append(((next_position, next_corners), action, 1))

```
在生成后继节点时，可以通过 `new_actions = parent_actions + [action]` 将本步动作追加到已有路径中，从而保证动作序列的完整性和顺序正确性。

无论使用广度优先搜索还是 `A*` 搜索，都在扩展节点时维护动作序列。当算法首次到达目标状态时，该节点所携带的动作序列即为完整路径，准确反映了智能体从起点到完成所有任务的整个移动过程。这种方法不仅保证了路径的完整性，还能够与搜索策略结合，实现最短路径或最优代价路径的输出。
