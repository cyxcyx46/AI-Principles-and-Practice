#### 搜索问题建模
搜索问题是人工智能与算法领域中的一个基础问题，其核心目标是在一个定义好的状态空间中，从给定的初始状态出发，通过一系列合法的动作，找到一条能够到达目标状态的路径。搜索问题并不是直接计算结果，而是通过系统地探索状态之间的转换关系来逐步逼近目标。因此，在正式进行搜索之前，必须对问题进行清晰、规范的建模，这也是搜索算法能够正确运行的前提。

一个标准的搜索问题通常由五个基本要素构成：状态 `state`、初始状态 `start state` 、目标状态或目标测试`goal test`、后继函数`successors` 以及路径信息。这些要素共同定义了搜索空间及其探索规则。

**状态**

状态是对问题中某一时刻“世界情况”的抽象描述。它只刻画当前情形本身，而不包含到达该情形的历史信息。一个合理的状态表示必须包含足够的信息，使得算法能够仅根据该状态判断是否为目标状态，以及可以执行哪些合法动作。同时，状态表示应尽量简洁，避免冗余信息，否则会导致状态空间不必要地膨胀，降低搜索效率。

```python
currstate = open.pop()

```
表示当前弹出的状态用于扩展。

```latex
s \in S, \quad S = \text{所有可能状态集合}
```

**初始状态**

初始状态是搜索开始时所处的状态，是整个搜索过程的起点。它是唯一确定的，并且作为搜索树或搜索图的根节点存在。所有搜索路径都必须从初始状态出发，逐步扩展到其他状态。因此，初始状态的正确性是搜索问题建模的基本前提。

```python
open.push(problem.getStartState())
goalpath = []

```
```latex
s_0 \in S, \quad s_0 = \text{初始状态}
```

`goalpath` 初始化为空列表，表示从起点还未执行任何动作。

**目标状态与目标测试**

目标状态指满足问题要求的状态，但在实际实现中，通常不会只用一个固定的状态来表示目标，而是通过**目标测试函数**来判断某个状态是否符合目标条件。目标测试是一种布尔判断，它使搜索算法能够灵活地处理单个目标或多个目标的情况。例如，在迷宫问题中，目标测试并不是判断是否等于某个固定坐标，而是判断当前位置是否位于任意出口位置。

```python
while not problem.isGoalState(currstate):

```
通过布尔函数判断某状态是否为目标条件。


**后继函数**

后继函数定义了状态之间的转换规则，即从当前状态出发，可以通过哪些合法动作到达哪些新的状态。后继函数通常返回一组结果，每个结果包含：后继状态、采取的动作以及对应的代价。搜索算法正是通过不断调用后继函数，逐步展开状态空间，构建搜索树或搜索图。
```python
for next, action, cost in problem.getSuccessors(currstate):
    if next not in closed:
        open.push(next)
        path.push(goalpath + [action])

```

```latex
Successors(s) = \{(s', a, c) \mid s' \text{由 } s \text{执行动作 } a \text{得到，代价为 } c \}
```

定义状态之间的转换规则，每个后继包含 (`next_state`, `action`, `cost`)。


**搜索节点**

在搜索算法中，真正被存储和操作的对象不是单纯的状态，而是搜索节点。搜索节点不仅包含当前的状态，还必须记录从初始状态到达该状态所经历的动作序列。这是因为搜索的最终目标不仅是找到一个目标状态，还需要返回一条可执行的解路径。

```python
goalpath + [action]

```
```latex
actions(s') = actions(s) + [a], \quad s' \text{由 } s \text{执行 } a \text{得到}
```

由 (`state`, `actions`) 组成，记录当前状态和从起点到该状态的动作序列。

因此，搜索节点可以理解为“状态 + 历史信息”的组合。同一个状态在不同路径下可能对应不同的搜索节点。

#### 深度优先搜索
深度优先搜索（ `Depth-First Search`, `DFS`）是一种**盲目搜索**策略，其核心思想是：优先向当前路径的最深层节点扩展，直到无法继续扩展时再回溯。

在搜索过程中，`DFS` 会沿着一条路径不断向下探索，而不会同时保留多条待探索路径。这种“先深入、后回退”的策略使 `DFS` 在空间利用上非常高效。

从搜索空间的角度来看，`DFS` 会尽可能快地到达搜索树或搜索图的叶节点，然后再回到最近的未完全展开节点，继续向下探索其他分支。

深度优先搜索通常使用**栈（ `Stack` ）来实现，这是因为栈具有后进先出（ `LIFO` ）**的特性，正好符合 `DFS` 的扩展顺序。

在 `DFS` 中：

- 每次将新生成的搜索节点压入栈顶;

- 每次从栈顶弹出一个节点进行展开。

这样一来，最近生成的节点会最先被展开，从而自然地形成“向深处优先”的搜索行为。

**DFS 的标准流程如下**：

1. 创建一个 `Stack`

2. 将起点压栈（状态 + 空 `action` 列表）

3. 初始化 `visited = set()`

4. 当栈不为空：

	- 弹出一个节点

	- 如果是目标 → 返回 `actions`

	- 如果未访问：

		- 标记 `visited`

		- 将所有 `successor` 压栈

5. 若搜索失败，返回空列表




#### 图搜索

在许多实际搜索问题中，状态空间并不是一棵严格意义上的树，而是一个图结构。不同的动作序列可能会到达同一个状态，甚至状态之间可能形成循环。如果在这种情况下仍然采用树搜索（ `Tree Search` ），搜索算法会将同一个状态视为多个不同的节点反复展开，不仅造成大量的重复计算，还可能因为循环结构而陷入无限搜索，导致算法无法终止。因此，当搜索空间中存在状态重复或回路时，必须引入更合理的搜索机制，这就是图搜索产生的直接原因。


在实际问题中，状态空间通常是图结构，同一状态可能通过不同路径被访问多次。若不控制重复扩展，`DFS` 可能陷入无限循环。

通过 `closed` 列表实现图搜索：
```python
if currstate not in closed:
    closed.append(currstate)

```
```latex
Visited = \{ s \in S \mid s \text{已访问} \}
```
每个状态最多被扩展一次，保证 `DFS` 图搜索的正确性。

**动作序列维护**

`DFS` 不仅要找到目标状态，还需要返回动作序列。实现方式：

1. `goalpath`：保存当前节点从起点到该节点的动作序列

2. 对每个后继节点生成新的动作序列：

   ```

   ```

3. 压入 `path` 栈，与 `open` 栈对应

