#### 宽度优先搜索基本思想
宽度优先搜索（`Breadth-First Search`, `BFS`）是一种典型的无启发式搜索策略。其基本思想是按层次顺序逐层展开节点，从初始状态开始，首先扩展距离根节点最近的节点，然后再逐步扩展距离更深的节点。与深度优先搜索不同，`BFS` 并不会沿着某一条路径一直深入，而是先将所有可直接到达的后继状态加入待扩展队列，然后按顺序逐层访问。这意味着算法会先访问所有与初始状态相距一步的节点，再访问距离为两步的节点，接着是距离为三步的节点，依此类推，逐层拓展整个搜索空间。

- 从初始状态开始，首先扩展距离根节点最近的节点；
- 然后逐步扩展距离更深的节点；
- 不沿某一条路径一直深入，而是先将所有可直接到达的后继状态加入**待扩展队列**，然后按顺序逐层访问。

在代码层面，这一“层次展开”的起点体现在**初始状态首先被压入队列**，作为第 `0` 层节点：

```python
open = util.Queue()
open.push(problem.getStartState())

```
随后，搜索始终从队列头部取出状态进行扩展，从而保证扩展顺序严格遵循层次结构：
```python
currstate = open.pop()

```

这种层次展开保证了 `BFS` 所找到的解是步数最少的。如果每一步操作代价相同，第一次到达目标的节点即为最短路径节点。此外，逐层扩展还为路径重建提供天然支持：每个节点在生成时都记录了从初始状态到该节点的动作序列，从而可以直接输出完整路径。

在实现中，“路径重建”并不是事后回溯，而是在**节点生成时同步维护动作序列**。例如，当从当前状态生成一个后继状态时，会立即构造其对应路径：

```python
path.push(goalpath + [action])

```
这意味着队列中的每一个状态，都与一条完整、可执行的动作序列一一对应。


**数学原理**：设状态空间图为 $$G=(S,E)$$，初始状态为 $$s_0$$，`BFS` 访问节点的顺序满足：
```latex
\text{distance}(s) = \min(\text{路径长度从 } s_0 \text{到 } s)
```
也就是说，算法总是先访问离根最近的节点，保证找到的解是最短路径。

#### BFS 的算法流程

广度优先搜索的执行依赖于**队列（Queue）**这一先进先出（ `FIFO` ）数据结构。队列的特点正好符合 `BFS` 的层次扩展策略： 新生成的后继节点被加入队列尾部；搜索节点从队列头部取出进行展开。

这一过程对应于以下两类操作：

```python
open.push(next)   # 新节点入队
currstate = open.pop()  # 取出最早入队的节点

```

在图搜索中，每个节点不仅保存当前状态，还要记录从初始状态到该节点的动作序列。例如，当从状态 `currstate` 生成一个后继节点 `next` 时，会把动作序列更新为 `goalpath + [action]` 并加入队列。这样，队列中每个元素对应一个状态以及从起点到该状态的完整动作路径。

这一同步更新体现在后继展开阶段
```python
for next, action, cost in problem.getSuccessors(currstate):
    open.push(next)
    path.push(goalpath + [action])

```
其中，`open` 队列与 `path` 队列在逻辑上保持一一对应关系。


为了避免重复扩展，每弹出一个节点前，需要检查其状态是否已访问。若未访问，则标记为已访问并展开后继；若已访问，则跳过。

这一“图搜索”机制通过 `closed` 集合实现：

```python
if currstate not in closed:
    closed.append(currstate)

```


**数学原理**：设状态空间 $$S$$ 和访问集合 $$Visited \subseteq S$$，`BFS` 保证每个状态最多被访问一次：

```latex
\forall s \in S, \quad s \text{最多扩展一次} \implies s \in Visited
```

每个 `BFS` 节点通常包含：

| 字段        | 作用                |
| --------- | ----------------- |
| state     | 当前状态              |
| actions   | 从初始状态到当前状态的动作序列   |
| cost  | 路径代价，如果每步代价相同，可省略 |

在实现中，这些信息并未封装为一个类，而是通过两个同步队列隐式维护：`open` 队列保存状态；`path` 队列保存对应的动作序列。

节点生成与动作序列更新逻辑如下：

1. 弹出队列头部状态 `currstate` 并检查是否为目标；
2. 若未访问，将其加入 `closed` 集合；
3. 遍历 `currstate` 的后继 `(next, action, cost)`：

若 `next` 未访问，将 `next` 压入队列，同时将动作序列更新为 `goalpath + [action]`。

```latex
actions(next) = actions(currstate) + [a], \quad (currstate \xrightarrow{a} next)
```

由于队列是 `FIFO` 结构，先生成的节点会先被弹出，这保证了 `BFS` 是按层次逐步扩展，第一次到达目标节点时所对应的动作序列即为最短路径。

#### BFS 的图搜索特性

`BFS` 的层次扩展策略结合访问集合 `closed` 或 `visited` 实现**图搜索**：

1. 每个状态最多被扩展一次；
2. 队列保证先生成的节点先访问；
3. 动作序列随节点生成而更新。

**数学表示**：
```latex
Visited = \{ s \in S \mid s \text{已访问} \}, \quad s \text{只会加入队列一次}
```

队列操作保证：

```latex
s_i \text{先入队} \implies s_i \text{先被扩展} \quad \Rightarrow \text{按层次展开}
```
